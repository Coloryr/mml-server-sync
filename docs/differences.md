# 与 MML 启动器原生同步的差异

本工具是**非 MML 启动器**（PCL2 / HMCL / Prism / MultiMC / 安卓启动器）的更新器；
MML 启动器自己启动游戏时会识别并跳过它，改用 MML 原生的 `serverpack` 同步。
两边读同一份 `server.json`，但下面这些能力/行为并不完全一样。

## 配置目录的四种同步方式

MML 的「配置文件」页不是只有压缩包一种做法，而是按目录选一种：

|  | 整棵子树 | 仅当前层 |
| --- | --- | --- |
| **压缩包** | 压缩包整包同步（`ArchiveAll`）：整包解压前先删旧目录 | 压缩包本目录同步（`ArchiveSelf`）：只覆盖当前层，不删客户端目录 |
| **逐文件** | 逐文件整目录同步（`FilesAll`）：子树里的文件逐个进 `Files` | 逐文件本目录同步（`FilesSelf`）：只有当前层的文件逐个进 `Files` |

另外还有两个辅助状态：

- **不同步**（`None`）：这个目录不参与同步，父目录整包时也会被排除；
- **删除目录**（`Delete`）：生成空 zip + `Over`，客户端据此删除该目录。

选择原则：

- 目录完全由发布端托管、不需要保留玩家私有文件 → **压缩包整包同步**，更新干净；
- 目录里还有玩家私有文件/子目录 → **压缩包本目录同步** 或 **逐文件本目录同步**；
- 需要逐文件增量、逐文件可选、保留清单外文件 → **逐文件整目录 / 逐文件本目录**；
- 玩家完全私有的目录 → **不同步**；
- 需要清理旧目录 → **删除目录**，不要靠删 `Archives` 条目。

## 总体约定

MML 只生成 `server.json`（以及 `.sha1` 指纹）；可选模组、四种配置同步方式所需的
`Files` / `Archives` 都在这一份清单里。`server.json.sync.json` **不是 MML 的设计**，
它是本更新器在逐文件模式下提供的客户端排除/强制删除扩展，思路对标 HMCL 服务器包。
**这是更新器扩展，MML 不提供**；MML 原生同步不生成也不读取这个旁文件，因此它只对
使用本更新器的启动器生效。正常发布优先按上面的四种方式选一种，逐文件模式确有需要时
再使用本扩展。

`server.json` 本身没有新增字段，MML 的 `server.json.sha1` 快速通道保持有效。

## 差异清单

| 功能 | MML 原生同步 | mml-server-sync | 说明 |
| --- | --- | --- | --- |
| 清单更新触发 | 先取 `server.json.sha1`，变了就下载清单并升级 | 同样先取 `.sha1`，变了就升级；不再用 `PackVersion` 短路 | 已对齐；发布端改了清单但没递增版本号时，更新器现在也会更新 |
| `.sha1` 缺失 | 启动路径需要一个可读的 `.sha1` | `.sha1` 取不到时退回下载整份 `server.json` | 更新器的容错分支；MML 生成的发布目录正常都有 `.sha1` |
| 自选模组是否下载 | 没勾选 → 不下载，旧文件保留 | 没勾选 → 不下载，旧文件保留 | 已对齐 |
| 首次同步的自选模组 | 本地没有时按 `.disabled` 安装 | 勾选后按原名下载安装 | 更新器的勾选是「本次是否下载」，配置类文件按原名才能被游戏读取 |
| 启用/禁用状态 | 更新时沿用本地已有文件名 | 更新时沿用本地已有文件名；不主动改回启用 | 已对齐；需要改状态时手动改名 |
| 自选模组选择记录 | 本地 `server.json` 的 `Skipped` | `<状态目录>/optional-state.txt` | 状态格式/位置不同，切换启动器时不共享；这是临时实现，后续会删除 |
| 旧文件删除 | 删除原名及 `.disable` / `.disabled` 副本 | 同样删除原名及两个停用后缀 | 已对齐 |
| 历史废弃 / 排除 | 不支持 `server.json.sync.json` | 支持 `Removed` / `Ignore` | **更新器扩展**，MML 不提供；MML 原生不会处理这两个字段 |
| 旁文件不存在 | 无关 | 按空规则处理，保留旧清单差异删除 | 只有网络故障、返回网页、JSON 损坏等无法确认的情况才停删除 |
| 实例版本 / 加载器 | 升级后回写实例的游戏版本、加载器、加载器版本 | 不回写 | 更新器只同步文件；MML 导出的 MMC/Prism 包里的 `mmc-pack.json` / `instance.cfg` 是静态的 |
| 在线信息 / 链接记录 | 更新在线信息表、清理 `mml-link` 映射 | 不维护 | 只影响 MML 自己后续的在线信息/链接展示 |
| 归档格式 | 支持 zip、tar、tar.gz、tar.xz | 只支持 zip | MML 生成的服务器包是 zip；从别处导入的 tar 包会有差异 |
| `Over=true` 覆盖 | 旧目录移走后解压 | 清理旧目录后解压（存在 `Ignore` 时保留命中项） | 两边都是整目录替换语义；`Ignore` 只在本更新器生效 |
| 空包墓碑 | 空 zip + `Over=true` 删除目录 | 同样删除；存在 `Ignore` 或旁文件读取失败时跳过 | 更新器的保护分支 |
| 下载/落盘 | 使用 MML 自己的下载器 | gzip 清单、`.part` 原子替换、瞬时错误重试 | 更新器特殊实现，文件结果语义不受影响 |
| 进度 / 取消 / 失败 | MML 启动器 UI | Swing 进度窗、暂停/取消、失败三选一、界面缩放 | 更新器特殊功能，保留 |
| 命令行 | 无 | `--force` / `--dry-run` / `--no-delete` / `--skip` / `--no-gui` 等 | 更新器特殊功能，保留 |
| 自更新 | 内嵌 jar 由 MML 打包 | 读取 `index.json`，下载到 `update/`，下次启动生效 | 更新器特殊功能，保留 |
| 自选模组简介 | 不读取 | 读取 `server.json.notes.json` | 更新器特有的发布端增强 |

## 结论

- 需要两边一致、且已经对齐的：`.sha1` 触发、未勾选不下载、旧文件删除包含停用副本。
- 明确保留的差异：sidecar 的 `Removed` / `Ignore`（更新器扩展，MML 不提供）、
  实例元数据回写（MML 有、更新器无）、归档格式（MML 更多）、本地选择状态（临时实现）。
- 更新器的 UI、失败弹窗、CLI、自更新、下载落盘细节属于「非 MML 启动器」入口的特殊功能，
  不要求 MML 跟进。
