# 与 MML 启动器原生同步的差异

本文对应当前 **1.9.0**。本工具是**非 MML 启动器**（PCL2 / HMCL / Prism / MultiMC /
安卓启动器）的更新器；MML 启动器自己启动游戏时会识别并跳过它，改用 MML 原生的
`serverpack` 同步。两边读同一份 `server.json`，但需要区分哪些是 MML 协议、
哪些是本更新器的扩展。

## 1. 协议边界

MML 的清单设计只有 `server.json`（发布时另生成 `server.json.sha1` 快速通道）：

- 可选模组：`Files[].Optional`；
- 配置同步：`Archives` / `Files` 两种载体，具体分成四种同步方式（见下一节）；
- 基础包：`Base`；
- 包版本、名称、游戏版本、加载器等：都在同一份清单里。

本更新器**不向 `server.json` 增加字段**，MML 的 `.sha1` 快速通道保持有效。

下面两个文件不是 MML 的设计，只由本更新器读取，需要发布端手动额外放置：

| 文件 | 用途 | MML 是否生成/读取 |
| --- | --- | --- |
| `server.json.sync.json` | `Removed` 历史废弃、`Ignore` 客户端保护 | 不生成、不读取 |
| `server.json.notes.json` | 自选模组简介 | 不生成、不读取 |

不存在这两个文件时，更新器按“没有扩展”处理，核心同步仍由 `server.json` 决定。

## 2. 配置目录：四种同步方式选一种

MML 的「配置文件」页不是只有压缩包一种做法，而是按目录选一种：

|  | 整棵子树 | 仅当前层 |
| --- | --- | --- |
| **压缩包** | 压缩包整包同步（`ArchiveAll`）：整包解压前先删旧目录 | 压缩包本目录同步（`ArchiveSelf`）：只覆盖当前层，不删客户端目录 |
| **逐文件** | 逐文件整目录同步（`FilesAll`）：子树里的文件逐个进 `Files` | 逐文件本目录同步（`FilesSelf`）：只有当前层的文件逐个进 `Files` |

另外还有两个辅助状态：

- **不同步**（`None`）：这个目录不参与同步，父目录整包时也会被排除；
- **删除目录**（`Delete`）：生成空 zip + `Over`，客户端据此删除该目录。

选择原则：

- 目录完全由发布端托管、不需要保留玩家私有文件 → **压缩包整包同步**；
- 目录里还有玩家私有文件/子目录 → **压缩包本目录同步** 或 **逐文件本目录同步**；
- 需要逐文件增量、逐文件可选、保留清单外文件 → **逐文件整目录 / 逐文件本目录**；
- 玩家完全私有的目录 → **不同步**；
- 需要清理旧目录 → **删除目录**，不要靠删 `Archives` 条目。

本更新器支持这四种方式；压缩包部分只支持 zip，MML 原生还支持 tar / tar.gz / tar.xz。

## 3. 已经对齐的行为

| 行为 | 说明 |
| --- | --- |
| 清单更新触发 | 先取 `server.json.sha1`，变了就按新清单同步；不再把 `PackVersion` 当作跳过条件 |
| 自选模组是否下载 | 没勾选 → 本次不下载，本地旧文件保留；勾选 → 下载/更新 |
| 启用/禁用状态 | 更新时沿用本地已有文件名；不会因为更新把 `.disabled` 改回启用 |
| 旧文件删除 | 删除原名及 `.disable` / `.disabled` 副本，与 MML 的 `delete_with_disabled` 一致 |
| 空包墓碑 | 空 zip + `Over=true` 删除目录；没有 `Ignore` 保护时两边一致 |
| MML 启动器下不双跑 | Agent 识别到 MML 启动器会跳过，由 MML 自己同步 |

## 4. 仍然不同的地方

### 4.1 首次同步的自选模组

- MML：本地没有该文件时，Optional 装成 `.disabled`；
- 本更新器：本地没有文件且勾选时，按清单原名下载安装。

本更新器的勾选语义是“本次是否下载”，配置类文件按原名才能被游戏读取；需要禁用时
可以手动改名。这个差异在 [optional-mods.md](optional-mods.md) 里也有说明。

### 4.2 自选模组选择记录

- MML：写在本地 `server.json` 的 `Skipped` 里；
- 本更新器：写在 `<状态目录>/optional-state.txt`。

两套记录不互通，切换启动器后选择不会自动带过去。当前实现后续可能调整。

### 4.3 实例版本、加载器和在线信息

MML 升级后还会：

- 回写实例的游戏版本、加载器、加载器版本；
- 更新在线信息表；
- 删除文件时同步清理 `mml-link` 映射。

本更新器只同步文件，不处理 `Loader` / `LoaderVersion` / `Icon` / `JvmArg` 等
实例字段，也不维护在线信息和链接记录。MML 导出的 MMC/Prism 包里的
`mmc-pack.json` / `instance.cfg` 是静态的；如果服务器包升级了 Minecraft 版本或
加载器，更新器不会改这些配置。

### 4.4 归档格式

- MML：zip、tar、tar.gz、tar.xz；
- 本更新器：只支持 zip。

MML 自己生成的服务器包使用 zip，所以正常 MML 包不受影响；从别处导入的 tar 包会有差异。

### 4.5 `.sha1` 缺失

- MML 启动路径需要一个可读的 `server.json.sha1`；
- 本更新器取不到 `.sha1` 时会退回下载整份 `server.json`。

MML 生成的发布目录正常都会带 `.sha1`，这个分支主要用于手工发布或调试。

### 4.6 更新器扩展：`Removed` / `Ignore`

`server.json.sync.json` 不是 MML 的清单设计，也不是第五种同步方式；它是本更新器
在逐文件模式下提供的客户端扩展，思路对标 HMCL 服务器包：

- `Removed`：历史废弃路径，首次同步或本地旧清单丢失时也能清理；
- `Ignore`：命中的文件不下载、不覆盖、不参与自选模组更新，也不被删除。

MML 原生不生成也不读取这个旁文件，所以它只对使用本更新器的启动器生效。旁文件不存在
（404 / 本地文件缺失）时按空规则处理，旧清单删除照常；只有网络故障、返回网页或
JSON 损坏等无法确认的情况才停掉删除。

### 4.7 UI、命令行、自更新和下载实现

这些是更新器入口的特殊功能，MML 不跟进：

- Swing 进度窗、暂停/取消、失败三选一、界面缩放；
- `--force` / `--dry-run` / `--no-delete` / `--skip` / `--no-gui` 等命令行参数；
- 读取 `index.json` 的自更新；
- gzip 清单、`.part` 原子落盘、瞬时错误重试。

## 5. 发布建议

- 同一份包同时给 MML 和本更新器用：**不要把关键删除/保护逻辑只放在
  `server.json.sync.json` 里**，MML 用户不会执行它。
- 配置目录优先按四种方式选一种；玩家私有目录用「不同步」，要删旧目录用「删除目录」。
- 只有确定只在非 MML 启动器上使用时，才依赖 `Removed` / `Ignore` 扩展。
- `server.json.notes.json` 同样只是更新器的可选展示增强，MML 不显示这些简介。

## 6. 一句话总结

**`server.json` 是 MML 和本更新器共同遵守的协议；四种配置同步方式和可选模组都以它为准。
`server.json.sync.json` / `server.json.notes.json` 是本更新器的扩展，MML 不提供；
发布时按目录选对同步方式，比在逐文件模式上叠扩展规则更重要。**
